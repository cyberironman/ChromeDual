# 打包与发布

面向要自己出 exe / 发 Release 的人。只想用的话看 [`使用说明.md`](使用说明.md) 就够了。

---

## 一、一句话构建

```bat
python installer\build.py --portable
```

产物全部落在 `release\`：

| 文件 | 给谁 | 说明 |
|---|---|---|
| `ChromeDual-Setup-<版本>.exe` | **普通用户** | 双击安装，建桌面图标、写卸载项、可选开机自启 |
| `ChromeDual-<版本>-portable.zip` | 想免安装的人 | 解压到任意位置就能跑（可选，`--portable` 才生成） |
| `SHA256SUMS.txt` | 发 Release 用 | 校验和，防止下载被篡改 |

只调主程序（快，调试用）：

```bat
python installer\build.py --skip-setup
```

## 二、环境要求

| 项 | 要求 | 备注 |
|---|---|---|
| 系统 | Windows 10 / 11 64 位 | PyInstaller 不能交叉编译，Windows 版本只能在 Windows 上打 |
| Python | 3.10 以上 | 本项目在 3.13 上验证 |
| PyInstaller | 6.0 以上 | `pip install pyinstaller` |
| 运行库 | `pip install -r requirements.txt` | 打包机器上必须先装齐，否则打出来的 exe 里没有这些库 |

## 三、打了两个 exe，各管什么

```
ChromeDual.py  ──PyInstaller──▶  dist\ChromeDual\ChromeDual.exe + _internal\
                                        │
                                        │ 整个目录被塞进安装器体内
                                        ▼
installer\setup_main.py ──PyInstaller──▶ dist\ChromeDual-Setup.exe
```

### 1. 主程序用 onedir（文件夹 + exe），不用 onefile

| | onefile（单文件） | onedir（本项目采用） |
|---|---|---|
| 冷启动 | 每次解包 90 MB，5-10 秒 | 1 秒内 |
| 杀毒软件 | 「自解压 exe」误报率高 | 正常 |
| 更新 | 整个重下 | 只换改动的文件 |

用户看不到 `_internal\` 这一堆，因为安装器把它整体装进固定目录，桌面只有一个图标。

### 2. 安装器用 onefile

安装器只跑一次，慢几秒无所谓；而且**必须是单文件**，否则用户会拿到一个「解压到哪」的哲学问题。

## 四、打包后还能找到资源吗：`RES` 与 `DATA_ROOT` 分开

这是整个打包改动里最关键的一件事，改错一点就是「双击没反应」。

| 概念 | 源码形态 | 打包形态 | 里面有什么 |
|---|---|---|---|
| `RES`（只读资源） | 项目根 | `_internal\`（PyInstaller 的 `sys._MEIPASS`） | `assets\`、`bin\`、`app\panel.html`、`config\*.example.json`、`tools\` |
| `ROOT`（程序目录） | 项目根 | exe 所在目录 | — |
| `DATA_ROOT`（可写数据） | 项目根 | exe 旁边**或** `%LOCALAPPDATA%\ChromeDual` | `config\`、`data\`、`var\`、`bin\xray.exe` |

规则：

* **`DATA_ROOT` 的挑选**：exe 所在目录可写就用它（绿色版），不可写（装在 Program Files）就用 `%LOCALAPPDATA%`。
  想强制指定，设环境变量 `CHROMEDUAL_HOME`。
* **内核 `xray.exe` 永远指向可写位置**（`DATA_ROOT\bin\xray.exe`）。
  程序自带的那份在 `RES\bin\xray.exe`，首次启动 `paths.ensure_core()` 复制过去。
  不然「换个内核版本」「下载内核」这些事永远做不了。

同时 `app\paths.py` 是**唯一**知道路径的地方，业务代码一律 `from app import paths` 再读属性 —— 所以只要这个文件判断对了，全项目都跟着对。

## 五、「再拉起自己」只能走 `app\selfrun.py`

源码形态和打包形态拉起的写法**完全不同**：

```
源码：  pythonw.exe  "D:\项目\ChromeDual.py"  --open profile-a
打包：  ChromeDual.exe                        --open profile-a
```

以前 `cli.py` 和 `tray.py` 各写了一份 `sys.executable.with_name("pythonw.exe")`，
打成 exe 以后就变成「拿 ChromeDual.exe 当解释器去执行一个不存在的 .py」——
双击桌面图标毫无反应，日志里只有一行看不懂的错。

现在统一收口在 `app/selfrun.py`，提供三个函数：

| 函数 | 用途 |
|---|---|
| `command(args)` | 拼出完整命令行 |
| `spawn(args)` | 后台拉起，不等它退 |
| `shortcut_target()` | 建 `.lnk` 用的（目标 exe，参数串，工作目录）三元组 |
| `pythonw()` | 写进注册表 / 快捷方式的解释器路径 |

顺带一个坑：`build_balancer_config.py` 这类「用 Python 跑脚本」的步骤，
打包后没有独立解释器。`app\line.py` 里对打包形态改用 `runpy` 在本进程内执行，
效果一样，但不再需要 `python.exe` 存在。

## 六、「缺什么就点一下装什么」是怎么实现的

`app\deps.py` 一层就够，但**分两种情况**，因为缺的东西根本不一样：

### 源码形态：缺 pip 包

`pystray` / `pywebview` / `psutil` / `pillow`。
缺了会抛一屏 `ImportError`，新手完全看不懂。

现在启动时（`ChromeDual.py` 里，**在 import `pystray` 之前**）先查，
缺就弹一个原生对话框列清楚，点「是」才联网装 —— 装的时候会临时挂一个控制台
显示真实进度（`AllocConsole`），装完自动继续启动。

### 打包形态：缺系统运行时和内核

pip 包都打进去了，缺的是这些：

| 缺什么 | 后果 | 怎么补 |
|---|---|---|
| **Xray 内核**（`bin\xray.exe`） | 一条线路都起不来 | 从 [XTLS/Xray-core](https://github.com/XTLS/Xray-core/releases) 下 `Xray-windows-64.zip`，自动解出 `xray.exe` |
| **WebView2 运行时** | 控制面板窗口打不开（托盘菜单还能用） | 微软官方 Evergreen Bootstrapper，静默安装 |
| **.NET Framework 4.6.2+** | pywebview 的 Windows 后端起不来 | 微软官方离线包（Win10/11 自带 4.8，基本不会遇到） |

内核不进 git 仓库是有意的：36 MB 的二进制会让 `git clone` 变得很痛苦。
所以从 GitHub 下载源码来用的人第一次启动会缺内核，程序会问一句、然后自己下。

### 界面为什么不用 tkinter

本项目用的 Python 是精简发行版，**没有 tkinter**；打进去还要多 10 MB。
所以依赖自检只用两样东西：

* `ctypes` 调 `user32.MessageBoxW` 弹原生对话框
* `kernel32.AllocConsole` 临时开一个控制台显示下载进度条

零第三方依赖，任何 Windows 都能用，打包也不会因为缺 tkinter 而失败。

### 手动复查

```bat
ChromeDual.exe --check
```

打包成 exe 后没有控制台，看不到 `print`，所以它同时把报告写到
`var\logs\deps-check.txt`。这一招在「双击没反应」的时候最有用。

## 七、安装器做了什么

`installer\setup_main.py`，纯标准库（tkinter、pywebview 都不用，因为
WebView2 正是它可能要修的东西 —— 不能自己先依赖上）。

六个步骤：

1. 检查运行环境（WebView2 缺就询问后静默装）
2. 关掉正在运行的实例（`OpenProcess` + `TerminateProcess`，不用 `taskkill`）
3. 复制程序文件（带进度条）
4. 创建桌面 + 开始菜单快捷方式
5. 写 `HKCU\...\Uninstall\ChromeDual` 卸载项（**只写 HKCU，不要管理员权限**）
6. 启动程序

**升级时一个字节都不碰用户的资料**：复制时遇到顶层 `config` / `data` / `var` / `logs`
且目标已存在，整棵跳过。登录态、Chrome 资料、备份全都在。

卸载走 `ChromeDual.exe --uninstall`（`app\uninstall.py`）：

* 问一句「资料要不要一起删」（一起删 / 只删程序保留资料 / 取消）
* 停掉安装目录里起来的进程
* 删快捷方式 + 注册表
* 交给安装目录**之外**的 PowerShell 延迟删除 —— 程序删不掉正在运行的自己

## 八、发版流程

```bat
:: 1. 改版本号（两处，必须同步）
::    installer\version_info.txt       filevers=(1,0,2,0)
::    installer\version_info_setup.txt filevers=(1,0,2,0)
::    installer\setup_main.py          APP_VER = "1.0.2"
::    CHANGELOG.md 加一节

:: 2. 构建
python installer\build.py --portable

:: 3. 上传 release\ 里的两个文件 + SHA256SUMS.txt 到 GitHub Release
```

> ⚠ 本机推 GitHub 有个坑：`github.com:443` 直连不通（`api.github.com` 反而正常），
> 而且环境里的 `http_proxy` / `https_proxy` 会让 git 走错代理报
> `502 CONNECT tunnel failed`。推之前先清掉：
> `env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY git push ...`

## 九、常见打包问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击 exe 没反应 | windowed exe 的异常看不见 | 跑 `ChromeDual.exe --check`，看 `var\logs\deps-check.txt` 与 `var\logs\app.log` |
| 控制面板空白 | 缺 WebView2 | 同上，`--check` 里会写着「WebView2: 未安装」 |
| 托盘不出来 | 缺 `pystray._win32` | spec 的 `hiddenimports` 里必须有它 |
| 面板窗口打不开但托盘正常 | `panel.html` 没打进包 | spec 的 `DATAS` 里要有 `app/panel.html` |
| 提示找不到内核 | `bin\xray.exe` 既不在 `_internal\bin` 也不在 `DATA_ROOT\bin` | 让程序下载，或手动把 `xray.exe` 放进 `DATA_ROOT\bin` |
| 打包报「找不到 dist\ChromeDual\ChromeDual.exe」 | 先打了安装器 spec | 用 `build.py`，它会保证顺序 |
| 打出来的 exe 有 100 MB+ | 忘了 `excludes` | spec 里已排除 `tkinter` / `PyQt*` / `numpy` 等 |

## 一、模块地图

```
ChromeDual.py          入口：--open <线路> / --target <网址> / 托盘
Tray/
  sysdefault_launch.py   接系统默认浏览器，参数**不自己拼**，交给管家算

app/                   真正的程序（只有代码，没有任何数据）
  paths.py             路径唯一来源；RES/ROOT/DATA_ROOT 三分；${ROOT} 展开；Chrome 自动探测
  selfrun.py           「再拉起自己」唯一出口（源码形态 vs exe 形态写法不同）
  deps.py              依赖自检与一键安装（pip 包 / 内核 / WebView2 / .NET）
  uninstall.py         卸载（--uninstall）：问资料、停进程、延迟删自己
  ports.py             端口随机分配 / 持久化 / 启动复核
  config_store.py      配置读写；首次运行从 example 生成
  bootstrap.py         没有内核配置时的占位直连配置
  guard.py             总控：线路集合、PAC、保活、重点网址
  line.py              单条线路：起内核、开窗、状态判定
  pac.py               PAC 静态服务 + 端口占位符渲染
  net.py               端口探测、站点探测
  procs.py             进程识别（区分自家内核与外人）
  login_guard.py       登录态守门员（纯只读）
  login_backup.py      登录态快照 / 恢复
  safety.py            破坏性操作门禁
  panel.py/panel.html  控制面板
  tray.py              托盘图标、菜单、控制口
  cli.py               命令行入口（控制口客户端）

installer/             打包与安装（只在发版时用，运行期不参与）
  build.py             一键构建；清不掉旧目录会自动改名让路
  build.bat            双击构建（CRLF）
  ChromeDual.spec      主程序 onedir
  ChromeDual-Setup.spec 安装器 onefile（把整个 dist 塞进自己体内）
  setup_main.py        安装器：六步、纯标准库、只写 HKCU
  version_info*.txt    exe 的版本资源

tools/
  build_balancer_config.py  订阅 → 探活 → 测速 → 生成 xray 配置
  bench_nodes.py            节点可用性与吞吐实测
  chrome_ai_cleanup.py      清本地 AI 模型 + 只读占位
  装成默认浏览器.py          注册 / 撤销默认浏览器条目
  救回登录.py                从快照找回登录 Cookie（只并登录类，最安全）
  检查残留.py                发布前自检：真实线路名 / 绝对路径 / 订阅地址是否混进来
```

**依赖方向是单向的**：`paths` ← `config_store` ← `line` ← `guard` ← `tray`。
底层模块不 import 上层，所以任何一层都能单独测。

## 二、几条不能破的规则

### 规则 1：路径只有一个来源

所有路径来自 `app/paths.py`，它按 `__file__` 推导根目录。
配置里可以写 `${ROOT}`，加载时由 `paths.expand()` 展开。

> **禁止**在任何业务代码里出现绝对路径字面量。
> 这条守不住，程序就会「在我机器上好好的」。

### 规则 2：端口不写死

`app/ports.py` 负责分配，槽位化：

| 槽位 | 含义 |
|---|---|
| `line:<线路 id>` | 该线路内核的 http 入口（socks = +1） |
| `pac` | PAC 静态服务 |
| `ctl` | 单实例锁 + 控制口 |

- 随机 → 写 `var/run/ports.json`（原子替换）→ 重启沿用 → 每次启动复核。
- 复核条件：越界 / 落在 10800–10999 / 被外部程序占用 / 与别的槽位重复。
- **自家内核正在听的端口视为可用**（不踢自己）。

改端口时**四个地方必须同步**，少一个就会出现「内核起来了但端口没就绪」：

1. `Line.sync_config_ports()` —— 内核配置里的 `http-in` / `socks-in`
2. `Line._run_build()` —— 调构建脚本时传的 `--http-port` / `--socks-port`
3. `Line.build_chrome_args()` —— `--proxy-server=http://127.0.0.1:<port>`
4. `pac.render()` —— PAC 模板里的 `__PORT_VIDEO__` / `__PORT_DEFAULT__`

### 规则 3：只改程序，不碰资料

**只改** `app\` `bin\` `config\` `tools\` `Tray\`；
`data\chrome\<线路>\` **一律不碰**。

永不 `copytree` / `move` / 改名资料目录。
真要换目录 = 这条线必须重新登录，得先告知用户。

### 规则 4：破坏性操作先问一句

`app/safety.py` 的 `guard()` 四步：

1. 查占用 —— Chrome 还开着就直接拒绝
2. 完整快照 —— Cookies + Login Data + Local State 成对；快照失败即拒绝
3. 明确确认 —— 交互输 `yes`，脚本用 `--yes`
4. 写审计日志 —— `var/logs/destructive.log`

### 规则 5：按需启动

管家启动**不预热任何内核**。`Line.desired` 标记「这条线现在有人用」，
保活线程只照顾 `desired=True` 的线路；`desired=False` 但内核还在 → 直接停。

窗口全关超过 `idle_stop_seconds` → 停内核，回待机。

## 三、为什么会掉登录（务必读）

Chrome 127 之后 Cookie 分两种加密：

| 版本 | 密文前缀 | 绑定对象 | 目录变了会怎样 |
|---|---|---|---|
| v10 | `7631` | Windows 用户 | 不受影响 |
| v20 | `7632` | `--user-data-dir` 绝对路径（ABE 应用绑定加密） | 解不开 → **Chrome 静默删** |

所以「所有网站同时退出登录、日志里一个字都没有」的成因只有三个：

1. 资料目录被复制 / 改名 / 换盘
2. Chrome 大版本升级（ABE 密钥轮换）
3. 跨线路恢复（Cookies 与 Local State 不成对）

**对策**（`app/login_guard.py`，纯只读）：

1. **路径冻结** `var/state/frozen.json` —— 登记后不许变；
   `Guard._check_login_paths()` 启动时校验，不符只报错、**绝不自动纠正**。
2. **开窗前体检** `line.open_chrome()` → `login_guard.before_open()` ——
   只读地数 Cookie（总 / v20 / 谷歌 SID）与两个密钥的 sha1，
   与 `var/state/login_state.json` 比较，变少就报警并写 `var/logs/login-events.log`。
   Chrome 独占锁住 Cookie 库时，用「复制到临时目录再读」绕过。
3. **一键找回** `tools/救回登录.py` —— 在历史快照里挑登录 Cookie 最多的一份，
   **只合并登录类 Cookie**，同 host+name 覆盖，其余不动。

> 判断「谁弄丢的」只看快照指纹，别猜：
> `var/backups/<线路>/<时间戳>/Network/Cookies` 逐个
> `select host_key,name,hex(substr(encrypted_value,1,3))`，
> 数 `v20`（前缀 `7632`）与 SID 家族。指纹一致 = 那段时间没动过。

## 四、启动与退出

```
ChromeDual.py
  └─ app.tray.main()
       ├─ App.__init__      Guard() → 分配端口 → 校验资料路径
       ├─ acquire_single()  读 ports.json 的 ctl → ping → 有 pong 就是已有实例，直接退
       ├─ _serve_control()  控制口线程（recv 4096，保留原文大小写）
       └─ _delayed_start()  start_passive() —— 只起保活线程，0 内核 0 PAC
```

退出：`stop_all()` → `Timer(2.5, os._exit(0))`。
**必须先停内核再退出**，否则会留下孤儿内核占着端口。

## 五、控制口协议

随机端口，指令名不区分大小写，**参数保留原文**（URL 不能被小写化）。

| 指令 | 作用 |
|---|---|
| `ping` | 存活探测，回 `pong` |
| `show` | 打开控制面板 |
| `up` | 全量启动（谨慎） |
| `quit` | 退出管家 |
| `open:<线路>` | 开该线路窗口 |
| `openurl:<线路>\|<URL>` | 起内核 + 在该线路开这个链接 |
| `ensure:<线路>` | 只起内核，不开窗口 |
| `opentarget:<重点网址 id>` | 按重点网址自动挑线路开窗 |

> 历史坑：原来 `recv(64)` 且整条 `.lower()`，
> URL 超过 64 字节会被截断、路径小写化会 404。现在读 4096、只对指令名做 `lower()`。

## 六、PAC 渲染机制

模板 `assets/pac/system.pac` 里写的是占位符：

```
var PROXY_VIDEO   = "PROXY 127.0.0.1:__PORT_VIDEO__; PROXY 127.0.0.1:__PORT_DEFAULT__; DIRECT";
var PROXY_DEFAULT = "PROXY 127.0.0.1:__PORT_DEFAULT__; PROXY 127.0.0.1:__PORT_VIDEO__; DIRECT";
```

`Guard._render_pac()` 每次启动 PAC 服务前现渲染到 `var/runtime/pac/`，
占位符换成本次随机到的端口。同时把模板里遗留的历史端口字面值一并替换掉。

哪条线路当「视频」、哪条当「默认」，由 `config/profiles.json` 的
`pac_server.video_line` / `pac_server.default_line` 决定；
没配就自动取「前两条走代理的线路」。

## 七、排查手册

| 现象 | 查哪里 |
|---|---|
| 内核起不来 | `var/logs/<线路>.log`、`<线路>-core.log` |
| 端口不响应 | 先 `kernel_alive()`，连续 3 轮才重启 |
| 面板打不开 | `var/logs/guard.log` |
| 登录掉了 | `var/logs/login-events.log` + `var/backups/` 指纹比对 |
| 点链接没反应 | `var/logs/sysdefault.log` |
| 破坏性操作被拦 | `var/logs/destructive.log` |
| 端口被谁占了 | `var/run/ports.json` + `app/net.py:port_listeners()` |

> 铁律：**绝不因「不归我管」就杀掉活着的内核**；
> 端口没响应时先确认内核是否还活着，别急着重启。
